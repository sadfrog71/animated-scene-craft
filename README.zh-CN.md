# Animated Scene Craft · 三维场景与游戏动画制作技能

[English](README.md) · [技能入口](SKILL.md) · [MIT 开源许可证](LICENSE)

面向 **Codex 的开源 Agent Skill**，用于三维场景制作、游戏动画、Blender 工作流和实时动画接入。它帮助智能体从用途、构图和空间关系出发，完成细节、动态、可编辑资产、导出检查和实际播放验证。

适用于角色与生物动画、交互机关、室内外环境、游戏空间、建筑场景、产品演示和离线动画。不限定写实或卡通风格，也不要求使用特定游戏引擎。内置执行脚本面向 Blender 和 FFmpeg；技能正文为中文。

## 效果图确认与完成度校验

新场景或重大美术改版先用 ImageGen 实际生成效果图，检查后展示给用户确认，再展开精细建模和批量制作。已有批准目标直接复用；明确只做灰模、技术验证或跳过效果图时遵循用户范围，不把沉默视为确认。

制作中保留“已确认目标图、上一版实景、本版实景”，在可比机位和状态下对照。可以用实际截图生成定向改善稿，但改善稿不算实现证据，也不能自动替换已确认目标。

在灰模、代表性组合场景和整体交付三个阶段检查内容完整、空间构图、美术完成度、动态交互与运行还原，分别给出 PASS / PARTIAL / FAIL / BLOCKED 和证据。不会凭感觉给整体完成百分比。完整规则见 [视觉目标与完成度校验](references/visual-completion.md)。

## 核心能力

| 能力 | 具体解决的问题 |
| --- | --- |
| 场景与视觉设计 | 从玩家行为推导构图、尺度、通路、遮挡、可达性及近看细节 |
| 有因果的自然动态 | 明确驱动力、挂点、支撑、幅度、节奏、相位和次级运动，避免所有物体机械同步 |
| 动画与玩法衔接 | 分清行为规则、世界位移、身体姿态和视觉反馈的控制权，处理动作切换与中断 |
| 资产导出一致性 | 将源工程、导出配置、必要后处理和运行资源对应起来，避免重导出丢失修正 |
| 实播与交互验收 | 正常速度检查完整动作、循环接缝、接触、穿插，以及实际输入和暂停恢复 |
| 有依据的性能优化 | 在目标设备测量后，再决定是否需要骨骼、GPU 形变、实例化、烘焙或层级细节 |

它不是游戏引擎、素材库、Blender MCP 服务，也不是一键生成完整游戏的程序。制作完整游戏时，会按需衔接已有玩法、输入、碰撞和验收工具；不会把静态场景或构建成功当成可玩交付。

## AI 主动识别动效与专项检查

由 AI 查看实际画面、场景结构、材质、玩法和参考资料，主动判断环境动态、交互响应、次级运动以及应保持稳定的对象，不要求用户逐项列出动效。复用当前模型的理解能力与现有检查工具，不额外部署识别模型或服务。

检查不仅覆盖已有动画，还检查应该有却遗漏的动态；在正常速度下核对可见性、挂点接触、节奏差异、因果响应、循环接缝、中断恢复、误运动及运行还原。静帧或参数变化不能证明动作完成。具体见 [动效识别与检查](references/motion-review.md)。

## 安装

已安装 Git，且 Codex 使用默认技能目录时：

```bash
git clone https://github.com/sadfrog71/animated-scene-craft.git ~/.codex/skills/animated-scene-craft
```

如果使用自定义技能目录，请替换目标路径。开始一个新聊天，检查技能是否可用。目标目录已有本地版本时，先备份或比较改动，不直接覆盖。通过 Git 安装的版本，可在确认本地改动后执行 `git pull --ff-only` 更新。

本仓库本身不要求 MCP、付费模型生成服务或额外游戏引擎。其他 Agent 工具可尝试读取 `SKILL.md`，但尚未验证其技能发现、工具权限与自动调用兼容性。

## 如何使用

在请求中写 `$animated-scene-craft`，并说明项目或素材在哪、玩家做什么、视觉方向、目标设备和本轮交付阶段。无需准备完整提示词模板。

### 制作可玩的游戏片段

> 使用 $animated-scene-craft，做一个小机器人探索房间、推动箱子打开通路的浏览器游戏。卡通风格，电脑操作，先交付一个可玩的关卡。项目目录是「路径」，沿用已有引擎，验证实际操作和动画效果。

### 优化已有角色动作

> 使用 $animated-scene-craft，优化「项目目录」里的走跑切换、转弯和落地动作。保留已有美术与玩法，检查接触、滑步和中断恢复，不重做无关内容。

### 制作并接入游戏资产

> 使用 $animated-scene-craft，基于这个 Blender 文件制作待机、行走和跳跃动画，用于我的 Godot 游戏。交付可编辑源工程与运行资源，并检查目标项目里的实际播放。

### 制作环境或离线动画

> 使用 $animated-scene-craft，完善这个庭院场景的树叶、布幔和水面动态。保留建筑与构图，根据各自运动原因设计变化，交付 Blender 源文件和正常速度预览。

仅讨论方案时，加上“先设计，不实现”。不确定技术路线时，可要求先检查现有项目再推荐方案。

## 工作方式与交付

先检查项目和资产，生成并确认必要效果图；灰模核对空间后，完成一个覆盖主要风险的组合区域或交互，对照目标、导出与实际运行效果后再扩展。已有定稿的局部修改直接修正，不强制重走完整制作流程。

按任务交付可编辑 `.blend`、制作脚本、引擎资源、运行页面、可玩游戏、连续帧或预览视频，并注明验证范围。本仓库不附带成品游戏或示范模型。

验收区分三个层次：

- **技术运行**：资源可读、动画推进、脚本或构建成功。
- **视觉播放**：实际视角、正常速度下的动作、接触与循环效果。
- **目标环境**：真实输入、目标设备、暂停恢复和性能表现。

没有设备或没有运行游戏时，明确保留待验范围，不用静帧代替实播。

## 内置脚本

```bash
python3 scripts/scene_tool.py --help
python3 scripts/scene_tool.py probe
```

`probe` 检查工具；`inspect` 读取场景；`run` 执行本次制作脚本并另存工程；`render` 渲染静帧或连续帧；`encode` 输出 H.264 视频。完整用法见 [执行路线](references/execution.md)。

命令入口使用 Python 3 标准库。场景操作需要 Blender，视频编码需要 FFmpeg；不会自动安装软件。只运行经过检查的制作脚本，执行器不是安全沙箱。场景检查不能覆盖全部缓存、几何问题或审美质量。

## 与其他技能协作

按需复用 Blender、环境美术、图像生成、Three.js 玩法、交互和游戏验收技能。具体名称见 [执行路线](references/execution.md)。这些技能不随仓库分发，也不会自动安装；缺失时应说明，并优先使用项目已有工具。

Unity、Unreal、Godot、原生应用或 Web 项目保持既有技术路线，不因使用本技能迁移引擎。完整游戏的玩法实现由相应能力衔接，本技能重点负责场景与动画质量。
