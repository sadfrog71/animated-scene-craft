# 动效识别与检查

适用于实时或离线动态场景。AI 主动推导动效需求并检查实际效果，不让用户承担逐件指出的工作。使用当前模型的图像、空间和行为理解及现有工具，不因此新增识别服务、分类模型或依赖。

## 从场景识别，不从已有动画清单倒推

实际查看参考图、已确认效果图、当前场景和可用播放证据，结合对象层级、材质、约束、玩法与可见范围判断：

- **持续或间歇动态**：场景设定中的驱动力与活动是什么，哪些对象会响应、哪些应保持静止。树木不必无风自动摇摆，机器不必关机仍转动。
- **交互和事件响应**：用户或角色做了什么，哪些部件、表面、声音或反馈应随之变化，何时结束或恢复。不能只补装饰性动效而遗漏操作反馈。
- **次级运动与关联**：主体变化如何传到附着物、接触物和周围介质；按质量、刚度、约束与风格决定差异，不把所有对象设为同幅同相运动。
- **稳定参照**：支撑、固定点、阅读区域、操作目标与不应运动的结构；镜头和环境动态不能让主要操作失去稳定性。

这些是推理角度，不是必须出现的特效清单。模型的推断不是事实：静态图看不出的驱动力、隐藏结构和行为规则，结合源码或工程核查；只有影响玩法、主题或明显制作成本的歧义才询问用户。授权内有依据的局部动效自主完成，不擅自新增天气系统、角色行为或玩法。

将高价值动态简短记录到现有制作判断中：**对象/区域、判断依据、运动或静止意图、触发/驱动力、约束与节奏、实际视角下的预期表现、证据与状态**。共享机制可分组，关键主体与例外单独检查；不要求为每片叶子建表。区分“必须实现”“可选增强”“有意静止/本轮不涉及”，不能在验收失败后无依据降级。

## 制作中的专项检查

代表性场景阶段就完成实际运动检查，再扩展；最终验收复查主要区域及相关状态。每轮根据以下维度选择受影响检查，同时回看是否遗漏应有动态：

| 维度 | 实际检查 |
| --- | --- |
| 覆盖与触发 | 应有动态是否实现、触发条件是否真的到达；持续、间歇、一次性动作分别验证。无动作可能是条件未触发，不直接判成失败 |
| 可见性与尺度 | 正常速度、目标镜头和观看距离下是否能感知；既不因幅度过小形同静态，也不为了证明在动而过度夸张 |
| 支撑与形变 | 固定点是否漂移，接触是否滑动，附着物是否脱离，结构是否穿插、拉伸或不合理变形 |
| 节奏与因果 | 启停、加减速、延迟、惯性和次级动作是否符合风格与事件；同源响应相关但不机械同步，避免无目的随机抖动 |
| 连续性与切换 | 循环首尾、动作转换、中断恢复是否跳变；非循环过程看完整变化，非周期动态看有代表性的状态和事件，不硬套循环要求 |
| 稳定与注意力 | 不该动的对象是否误动；环境、镜头和特效是否抢夺操作注意或遮住信息；图层动画是否拖动背景、破坏遮罩或反射关系 |
| 运行一致性 | 源预览与最终输出/引擎的方向、时长、节奏和附着关系是否一致；实时任务再检查暂停恢复、已有减少动态设置与相关性能 |

## 证据与修正

先看组合后的正常速度实播，再对有问题的对象局部检查。慢放、放大、轨迹或数值采样可诊断问题，但不代替正常速度下的观感判断。覆盖完整动作/循环和必要触发状态；不设通用秒数或运动幅度阈值。

连续播放或可查看的视频用于判断节奏与流畅度；带时间戳的连续帧可检查姿态和位移，但稀疏截图不能证明动作流畅。只能获取帧或数值、无法查看播放时，明确哪些时间性结论尚未验证，不宣称已经观看视频。生成视频也不能替代真实模型或游戏的运行证据。

按 [完成度校验](visual-completion.md) 的 PASS / PARTIAL / FAIL / BLOCKED 记录重要动态及其证据。有帧变化但动作不可辨认、动作明显不合理或用户无法正常操作，不能标为通过。无证据的项目注明未验证；有意静止的对象核查其稳定性，不为了覆盖率强行动起来。

发现问题时记录位置/时间或触发条件、可见差异、原因假设、修改与复查结果。优先修复遗漏的关键反馈、错误约束和明显跳变，再调整幅度、节奏与次级效果；不靠全局加速或放大掩盖实现问题。修复后复查局部和整体，避免局部自然但全场过度运动。
