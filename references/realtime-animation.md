# 实时动画制作与接入

适用于角色、生物、机关、环境与交互动画。沿用现有引擎和工程，不把 Blender、GLB、Three.js 当作所有游戏的必选组合。以下记录合并进项目已有资产清单或任务记录，不另建通用平台。

## 1. 先分清行为、位移与姿态

| 职责 | 需要明确的决定 |
| --- | --- |
| 行为与规则 | 为什么行动、目标是什么、什么时候开始/结束、能否中断；由已有玩法逻辑负责 |
| 世界位移 | 导航、控制器、物理或动画根运动中谁拥有最终位置与朝向；避免两个系统同时推动主体 |
| 身体与部件动作 | 骨骼、形态键、刚体部件或程序形变表达姿态、接触与次级运动 |
| 表面与反馈 | 着色器、粒子、音效、界面或镜头响应，跟随明确事件和设置 |

按实际需求组合，不要求每个对象都有四层代码。程序动画适合参数连续变化和交互响应；关键帧/骨骼适合需精修的动作；模拟适合确有动态接触需求的对象。不要把所有运动简化成正弦摆动，也不要为了自然感默认增加物理引擎。

动作应与行为关联：速度变化影响步幅或摆动，转向带动身体姿态，停止后按风格进入稳定状态。允许卡通夸张与刻意非写实，验收依据用户风格和玩法可读性，不强制物理写实。根运动须明确世界位移的交接；原地循环须与控制器速度协调，避免滑步或双重位移。

## 2. 用最小动作约定连接制作与程序

对实际要接入的片段记录必要字段：稳定名称、用途、循环/单次、入口与退出条件、混合或硬切策略、影响的骨骼/对象，以及必要的动作事件。简单环境循环只需名称和循环方式。

- 同一角色的互斥动作不能在加载时全部播放；叠加动作要明确作用范围、权重与优先级。只有确实需要切换时才引入相应控制，不为单循环搭复杂状态机。
- 攻击接触、脚步、开门完成等时机与可观察动作对齐。命中、奖励等玩法结果由既有规则系统裁定，不因视觉片段结束便自动视为成功；暂停、重播或中断不能重复结算同一事件。
- 交互发生后明确恢复位置：继续、重启还是转入另一动作。镜头、声音和特效跟随同一事件，不各自用无关计时器猜测时机。
- 先验证一条代表性转换及其打断，再扩展动作数量。已有状态和事件机制够用时直接复用。

## 3. 可编辑源文件到运行资源保持一致

把源工程、导出设置、必要后处理与最终资源建立可追溯对应；使用现有版本号、清单或哈希即可。重导出应能复现已确认修正，不靠记忆手动补丁。

- 检查尺度、轴向、挂点、层级、绑定、片段命名、时长和循环边界。换装、挂件、文字和碰撞体按实际需要确认跟随关系。
- 先验证一个代表性资产在目标加载器内的效果，再批量制作。制作软件支持的约束、驱动、节点、模拟、材质或缓存，不等于交付格式与目标引擎也支持；按实际版本检查导出能力，选择烘焙、转换或运行时实现。
- 若必须修补导出文件，将修正回写源工程，或保留可重复执行的后处理和适用输入检查；不要只保留一份无法重建的成品。避免重复运行时累加变换或重复节点。
- 对比源预览与实际运行资源的关键姿态、完整循环和接触点；源软件正常、文件导出成功、引擎加载成功分别只证明对应环节。

Blender → glTF/GLB → Three.js 路线可用已有动画片段与 AnimationMixer；其他引擎使用原生动画系统。需要具体 API 时查当前版本官方文档，不复制过时配置或据此迁移引擎。

## 4. 时间与性能按实际设备验证

明确动画使用游戏时间、真实时间还是固定模拟步长，沿用工程的时钟与更新顺序。恢复前台或长帧后按语义选择暂停、有限追赶或跳到当前环境状态，不无条件补算全部时间，也不无条件截断所有动画时间。

先测量再改实现：区分加载耗时、CPU 更新、GPU 绘制、帧时间波动与资源占用，记录设备、分辨率、场景规模和基线。逐顶点更新、法线重算、骨骼数量、透明叠加等只是检查候选，不凭源码就宣称性能瓶颈。

只有证据支持时才采用骨骼/GPU 形变、实例化、烘焙或层级细节等优化，并复查外观、交互与编辑成本。无目标设备时明确限制，不虚构通用面数、帧率或收益指标。

## 5. 在玩家入口验收

涉及视觉完成度时，同时按 [视觉目标与完成度校验](visual-completion.md) 对照批准目标和实际画面；本节补充动作与操作证据，不重复建立另一套验收记录。

按受影响内容选检查，不为每次小修改完整重测游戏：

- 正常速度看完整循环或完整动作，包括首尾接缝、脚/轮/挂点等接触关系、穿插和形变。
- 实际输入触发进入、转换、中断与结束；需要重试、重生或读档的游戏核对相应状态恢复，环境展示不强加这些流程。
- 在实际镜头与观看距离判断动作是否看得清、能否预判交互；按用户目标检查自由视角、触控或移动端。
- 验证暂停/恢复、前后台及已有减少动态设置；减少装饰动态时保留必需玩法反馈，可采用更稳定的替代表达。
- 保留同条件基线与正常速度实播证据。参数、像素或骨骼变换检查证明运行状态，实际播放与操作才支持观感和玩法结论。

交付注明源工程、运行资源、实际入口及已验证/待验证范围。没有运行游戏时，只报告制作或导出检查，不称为可玩验收通过。
